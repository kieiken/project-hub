保存先は既存の `HUB_ROOT`、番号は `HUB_PORT`（既定4545）。既存のサーバーへは接続しません。同じ保存先の専用窓や使用中の番号は拒否します。名前付きMutexを保持し、本体のPID・コードの場所・保存先・起動識別・世代を照合します。管理者として開かれた窓は拒否します。

Windowsの保存は、固定のローカルNTFSと再解析点のない保存先を確認し、ファイルをFlushFileBuffersで確定してからMoveFileExW(REPLACE_EXISTING|WRITE_THROUGH)で同じボリューム内の名前変更を行います。従来のボリューム全体への管理者用flushは使いません。共通のsyncDirectory/withDirectorySyncのWindows実装は保存先の同一性検査であり、ディレクトリ内容の永続化を保証しません。ファイル名の変更・リンク・削除の直後の停電に対する確実さは、従来より弱くなり得ます。本人が2026-10-19に承認したWindows限定の境界です。Mac/Linuxは従来どおりです。失敗は成功に読み替えません。

内部移動は起動した127.0.0.1の同じ番号だけです。利用者が開く外部HTTP/HTTPSは通常のブラウザへ渡します。外部フレーム・外部リソース・権限要求・ダウンロード・ホストオブジェクト・WebMessage・開発者ツールは拒否/無効です。ファイル入力と貼り付けは表示部品の標準機能です。Mac専用の操作は移植しません。利用権保管は既存のCredential Manager/DPAPI・SQLite実装を保持し、本番の購入受付は準備中です。隔離実行はCodex CLIのsandbox（`codex sandbox`、elevated方式の初期設定済み）とGit for Windowsのbash.exeを使います。無い場合は従来どおりコマンドを拒否します。Codexは対象フォルダのNTFS ACLにサンドボックス用アカウントの項目を追加し、実行後も残します。自動更新の実装候補と未確認範囲は後述します。

## Windows自動更新（実装候補・実機未確認）

専用窓から起動した一般版 x64 が対象です。自動更新は初期状態でオフです。ブラウザ起動・製作者版・別のCPUでは有効にしません。Gitの取得や依存部品の自動導入は行いません。

固定のWindows用feedとEd25519署名・連番・期限・対象OS/CPU・Nodeの条件を確認し、ZIPのサイズ/SHA256を照合します。ZIP内の絶対パス、親への移動、別ストリーム、リンク、Windows予約名、重複、解凍量超過を拒否します。展開後のファイル名と内容の署名対象指紋も確認します。配布物はリリース担当がWindows用依存部品を準備した `hub/` フォルダです。Windows用node-ptyやWebView2関連DLLをMacの部品で代用しないでください。

版は `HUB_ROOT/_hub/updates/windows/versions/` に保持します。更新記録・current/previous・起動確認票は同じ保存先の `update.sqlite` にSQLite WAL/FULLの1トランザクションで記録します。計画時のJSONの名前変更方式から、既存の一般ファイル保存の停電保証に依存しない方式へ変更しました。固定ローカルNTFS・再解析点なし・本人専用ACLと親の書換権限を検査し、共有された保存先では止めます。元の起動フォルダ、前版、利用権DB・DPAPI・Credentialは置換/削除しません。

最初の元フォルダの `start-window.cmd` を引き続き使います。元のランチャーが署名とファイルを確認してから、新版のサーバーを起動します。AI・順番待ち・整理等の処理、入力中の文がある間は開き直しを待ちます。起動した本体と窓の一致・保存と正常終了・空きポートを確認してから切り替えます。新版の完全なローカル一覧応答と復元完了・版/場所/確認票が一致した時だけ起動成功とします。

新版の起動に失敗した場合、対象の本体と窓が止まったことを確認できれば前の版へ戻します。確認前に電源が切れた場合も、次回起動時に未確認票を読み、最大2回の確認後に戻します。停止を確かめられない時は強制終了せず、窓と記録を残します。失敗した同一配布物を自動再適用しません。受入済みの版はfeedの有効期限が過ぎても起動できますが、署名・失効鍵・指紋の確認は省きません。
