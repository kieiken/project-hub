# Project Hub

[繁體中文版](README.zh-TW.md) — `HUB_LANG=zh-TW`（未設定は日本語）。

今の版は `package.json` の version（画面の左上にも出る）。変更の記録は [CHANGELOG.md](CHANGELOG.md)。

プロジェクトと作業を一覧にして、画面の中で Claude Code / Codex を動かす管理ソフト。1人で使う Mac の中だけで使う。使う前に「使う前に知っておくこと」を読んでください。

## はじめて使う時（1回だけ）

前提：Node.js 22 以上、Git。使う AI の CLI（Claude Code / Codex）を入れてログインしておく。Apple の開発ツール（無ければ setup.sh が導入の窓を出して止まるので、導入が終わったらもう一度実行する）。

配布元から取得したフォルダに移り、その一番上（`hub/` が入っている所）で実行する：

```
cd "<取得したフォルダ>"
bash hub/setup.sh
```

- 何度実行しても大丈夫
- `~/Documents/AI-Workspace/` に `_hub/`（役割分担 `roles.yaml`）・`Product/`（台帳）・`Work/`（作業用コピー）ができる。場所は `HUB_ROOT` で変えられる。すでにある roles.yaml と台帳は触らない
- `hub/seed/` の架空のサンプル台帳を `Product/` に写す。実際のプロジェクトや作業記録ではない。見本のフォルダパスは自分の環境に合わせて変更する
- npm で作業画面の部品（node-pty）を入れる。入らなくても管理ソフトは動き、作業は別の窓で開く
- デスクトップに「Project Hub」ができる

## 使う前に知っておくこと

- **1人で使う Mac 用**：本体が待ち受けるのは `127.0.0.1:4545` だけ。Host・Origin は確かめるが、利用者の認証は無い。外向けの Web サービスや共有サーバーとして配ったり動かしたりしない
- **AI の許可確認**：既定では Claude Code を `--dangerously-skip-permissions`、Codex を `--dangerously-bypass-approvals-and-sandbox` で起動する（`lib/launch.js`）。Claude Code は許可確認を省き、Codex は許可確認とサンドボックスを省く。AI は利用者の権限で、ファイルを書き換えたりコマンドを動かしたりできる。変える時は `_hub/roles.yaml` の `permissions` で起動のしかたを指定する
- **写される設定**：作業用コピーを作る時、本体の一番上にある Git に入っていない `.env`・`.env.*`・`.dev.vars`・`.dev.vars.*`・`.npmrc` と `.claude/settings.local.json` を作業用コピーにも写す（AI のテストを動かすため）
- **自動の Git 保存**：作業前の保存・最初の保存・作業用コピーの取り込みでは、`git add -A` してからコミットする。コミットはターミナルの確認を出さずに行い、`--no-verify` なので pre-commit などのフックは動かない。Git の名前が未設定なら `Project Hub <hub@localhost>` の名前で保存する
  - 新しく加わる `.env` 系・`.npmrc`・`.dev.vars` 系・`.claude/settings.local.json` は保存から外す。先に手で `git add` していても新規の対象ファイルは外し、ファイル自体は手元に残す。例示用の `.env.example`・`.env.sample` は保存する
  - すでに Git に入っている物、Hub を通さず手動でコミットした物、別の名前の秘密ファイルは守れない。秘密が入らないことは保証しない。必要なら各プロジェクトの `.gitignore` で除外する
- **手元に残る記録**：会話 `.ai/chat/`、引き継ぎ資料 `.ai/handoff/`、操作の記録 `_hub/log.jsonl`、渡したファイル `AI-Workspace/Inbox/hub/`。どれも暗号化されずにそのまま残る。Git のある既存プロジェクトでは会話や引き継ぎも自動保存で履歴に入ることがあるため、除外する場合は各プロジェクトの `.gitignore` に書く。新規プロジェクトのひな形には除外規則が入っている。共有や公開の前に中身を確かめる
- **料金**：実際に AI を使った分は、各 AI CLI 自身のプラン・料金・ログインの設定に従う。Hub は料金がかからないことを保証しない
- **外へ送る操作**：作業の内容を第三者のサービスへ送る操作（公開・投稿・送信など）は、Hub の仕組みとは別に、人がそのつど承認してから行う前提

## 毎回

デスクトップの「Project Hub.app」をダブルクリック → 専用の窓で開く。ターミナルは要らない。
初回だけ「書類フォルダへのアクセス」を聞かれるので「許可」。

- アプリ（`app/window.swift`）が本体（node server.js）を自分で起動し、Mac 内蔵の WebKit で画面を出す
- 窓を閉じても、本体と作業中の AI は裏で動き続ける。次に開くとそのまま続きが見える
- 失敗した時は窓の中に理由が出る。記録は `~/Library/Logs/ProjectHub.log`（メニューの「記録を開く」）
- `app/build-app.sh` がアプリを作り直す（setup.sh も呼ぶ）。更新した後はこれを実行
- 名前変更などの入力ダイアログでも ⌘V で貼り付けられる。この修正を含む更新では、Hub本体の版切替に加えてMacアプリも作り直す
- ターミナルから起動したい時は `bash start.command`

## できること

- **ファイル・フォルダのリンク**：押すと開き方を選べる。ファイルは［元のファイルを開く］か［Finderで表示］、フォルダは［Finderで開く］か［中身を見る］。コピーをダウンロードせず元の場所を使う。Macアプリ・Macのブラウザで利用できる

- **整理・動作検証**：候補の取得状況が表示される。候補を選ぶと［ゴミ箱へ移す］が使えるようになり、整理の記録から復元できる。取得を中止した場合は理由が表示される。構造確認では資料の相対パスをプロジェクトの場所から確認する
- **左の木**：プロジェクトの下に作業がぶら下がる。分かれた作業（分岐元のある作業）や小分けのプロジェクトは一段下に「↳」付きで出る。「⑂2」は分岐の数
- **概要画面**（プロジェクトを押す）：説明・作業の一覧・フェーズと担当・問題点・関連プロジェクト。［ファイルを見る］で中身のある場所を開く（場所が複数なら選ぶ）
- **会話画面**（作業画面の［会話］。いつもはこちら）：Goose のように1本の会話で、送るたびに答える AI とモデル・思考を選ぶ。返事には誰が答えたかの印が付く。AI を変えると、その AI がまだ見ていない会話（人と AI の文字だけ）を引き継ぎとして一緒に渡す。同じ AI の続きは、その AI 自身の会話を再開する。会話は `.ai/chat/<作業ID>.jsonl` に残る。中では `claude -p --output-format stream-json` と `codex exec --json` を1回ずつ動かす（`lib/chat.js`）。途中経過を細かく見たい時は［ターミナル］に切り替える
- **プロジェクトの丸**：灰＝まだ始めていない／赤＝AI が作業中／薄緑＝処理が終わった／紫＝完了（プロジェクトの画面の［プロジェクトを完了にする］を押した時だけ。［完了を取り消す］で戻せる）。下の作業の丸も同じ色で、黄＝あなたの返事が必要
- **場所と URL**：会話・質問の中の📁付きの場所を押すと、フォルダは画面の中に中身の一覧、ファイルはそのアプリで開く（［Finder で開く］も選べる）。URL は押すとブラウザで開き、⧉ でコピー
- **細かい作業**：コマンドなどの細かい作業は、最初は会話に出さない。設定画面の「会話画面」で出せる
- **ファイルの許可**：書類などのフォルダを読めない時は、設定画面（またはアプリのメニュー）の［確認をもう一度出す］で Mac の確認を出し「許可」。出ない時はフルディスクアクセスに入れる
- **AI の質問**：会話画面で AI が判断を聞く時は、選択肢のボタンが出る。押すと答えを送る（作業は返事待ち＝黄色になる）
- **モデルの一覧**：選ぶ欄には CLI が今使えると答えたモデルだけを出す。設定画面の「選ぶ欄に出すモデル」で隠せる。［最新のモデルに整理する］で役割の古いモデル名を新しいものに
- **AI から AI へ渡す**：AI は Hub の /api/delegate で渡す決まり。同じ作業・会話で担当 AI を切り替え、動いている AI があれば終了後の順番待ちにする。子作業は増えず、待ち順と実行中の AI・モデル、結果を画面で確認できる。委任には model 又は主担当の role を明示する。正式名（例：claude-fable-5-1）も指定でき、指定が無い・使えない時は理由を返して停止する。ターミナル稼働中は委任できず、同じ作業を会話画面で再開するよう案内する。起動失敗で状態や質問を消さず、完了済みの作業へは人が再開するまで委任しない。Hub を通さず裏で起動された AI も見張って「裏で作業中」と出す
- **子プロジェクト**：［子プロジェクトに分ける］で同時に始める。子が終わると結果が親の作業と会話に入り「新」が付く。子が途中で親を進めようとすると知らせる
- **ChatGPT**：設定の［ChatGPT アプリ（Codex）に登録する］で Hub の道具を登録。担当に「ChatGPT」を選び、「ChatGPT に貼る文」をアプリに貼ると、ChatGPT が作業を読んで結果を書き戻す。「実作業もできる」はオフが既定
- **外から使う（iPhone）**：設定でオン＋合言葉。Mac と iPhone に Tailscale を入れ、Mac で `tailscale serve --bg 4545`。iPhone で `https://<Macの名前>.<tailnet>.ts.net` を開き、合言葉を入れる。ログイン後は Mac と同じ操作ができ、処理は接続先の Mac で実行される
- **未読と GitHub**：見ていない間に AI の作業が終わると左の一覧に「未読」。作業の会話を開くと消える。取り込んで片付けた作業の通知も消え、完了済みの未読作業は読むまで左に残る。本体が GitHub にあれば［GitHub］で開く（作業用コピーはその枝）
- **すぐ始める**：プロジェクトの画面で、やりたいことを書いて［始める］。作業ができ、会話画面で AI に送られる。左の欄で担当AI・モデル・思考を選べる。プロジェクトごとに前回の担当を覚え、初回はClaude Code。文章と添付画像は再描画・切り替え・再起動でも残り、成功したら入力欄を空にする。画像はドロップ・⌘V・📎で最大10枚（png/jpg/jpeg/webp/gif/heic）を追加し、×で取り消せる。画像だけでも開始できる。作業フォルダの attachments/<作業ID>/ に元画像と必要に応じてPNGをコピーし、ClaudeにはRead指示、Codexにはexec -i、Agyには画像の場所を渡す。GIFは最初のフレームをPNGとして渡す。Discordは送信機能がないため依頼と画像の場所を保存し、作業画面に未送信と手渡しの案内を出す。細かく決める時は「＋ 細かく決めて作業を足す」
- **会話欄の画像プレビュー**：画像をドラッグまたは⌘Vで追加すると、依頼の上に小さく表示。×で送信前に取り消せる。画像だけでも送れ、画面切り替え・再描画・送信失敗でも添付を保持する（再起動後の復元は始める欄のみ）。送る時に画像の場所を依頼に添える。画像以外のファイルは従来どおり場所を本文へ入れる。
- **作業中の指示**（会話画面）：AI が作業中に書くと［① 取り消してやり直す］［② 追加説明（一緒にやる）］［③ 終わったら次に］を選べる。③は並べておくと順に自動で始まる（保存するので再起動しても残り、止まっている時は［▶ 始める］で送れる）。［止める］は待っている指示も取り消す
- **新しいプロジェクト**：左の一覧の下の［＋ 新しいプロジェクト］。名前・説明・フェーズ（本体のフォルダ・親・関連は「くわしく」）を入れると、台帳と AI 用の指示と作業用のフォルダを作る
- **作業画面**（作業を押す）：窓いっぱいに AI の作業画面。［Claude Code で始める］［Codex で始める］で起動、もう一方も［＋ 並べる］で左右に並べて同時に作業
  - ［○○に交代 →］：上限の時・モデルを変えたい時に。前の AI の会話（人と AI の文字だけ。道具の結果・添付・隠れた推論は除く）を `.ai/handoff/` の引き継ぎ資料にまとめ、相手の AI に読ませて続けさせる。相手が動いていなければ役割どおりのモデル・思考で始める。相手が作業中なら断る。会話は Claude Code・Codex の記録（~/.claude・~/.codex）から読み、読めなければ画面の文字で代わりにする。6万文字を超えたら古い方を省き、省いたことを資料に書く（元の会話ログは削除しない）（参考: arumwu/goose-acp-handoff の考え方。Goose には依存しない）
  - AI の見出しのモデル・思考を変えると、動いている AI に `/model`・`/effort` を打って切り替える（作業ファイルにも残る）
  - ［始める］を押すと、Git のあるプロジェクトは作業ごとの作業用コピー（`Work/<プロジェクト>/<作業ID>/`）を自動で作り、そこで AI が作業する。Git の無いプロジェクトは保存を始めて本体で作業（始める前に毎回保存）
  - ［取り込み対象から外す］：本体へ取り込まず、取り込みボタンと差分予告を非表示にする。作業用コピー・ファイル・再開先は残り、あとで［取り込み対象に戻す］で戻せる。除外中も同じ場所で作業でき、残存コピー数には含まれる
  - ［本体に取り込む］：作業用コピーを本体に取り込み、作業用コピーはゴミ箱へ。ぶつかった時は取り込まず「あなたの番」に出す。AI が動いている間は押せない
  - 下の段で、状態・メモを変えられる（AI が動いていない時は、次に始める時のモデル・思考もここで選ぶ）
- **担当と進み具合**：担当は色と形で見分ける（丸＝Claude Code・Codex、角＝Discord のエージェント、黄＝あなた）。作業ファイルの「## 手順」の数で進み具合の棒を出し、全部終わると完了
- **フェーズ**：概要画面の上に道のりとして並べる。今のフェーズの作業が全部終わると COMPLETE と［次のフェーズへ進む］。作業の一覧は今のフェーズの分だけ（他は畳む）
- **通知の意味**：左の一覧に「未読」「返事待ち」「完了確認」を文字で表示。未読はまだ開いていないAIの結果、返事待ちは質問・上限停止・AIが1分以上入力を待っている作業、完了確認は［完了に移す］か［まだ続ける］の判断待ち。質問もある作業は返事待ちに数える
- 「あなたの番」：上のボタンに返事待ちと完了確認の件数を別々に表示。同じ名前のタブで対象を開き、返事や完了の判断をする
- **作業中／入力待ち**：AI の画面が20秒止まったら「入力待ち」と出す（Claude Code・Codex は作業中ずっと表示が動くため）
- **取り込む前の見通し**：［本体に取り込む］の横に変更の量（ファイル数・行数）と「本体とぶつかりそう」を出す
- 作業用コピーを作る時、Git に入っていない手元の設定（.env など）も写す
- **ファイル・スクショを渡す**：作業画面の AI の画面に落とす（または ⌘V で貼る）と、`AI-Workspace/Inbox/hub/<日付>/` に保存し、その AI の入力欄にファイルの場所を入れる（続けて指示を書いて Enter）。作業ファイルのメモにも残るので、もう一方の AI や次の AI も読める。AI が動いていない時は保存と記録だけ
- **操作の記録**：始めた・止めた・渡した・取り込んだ等を `_hub/log.jsonl` に残す（設定画面の「最近の操作」）
- 参考にしたもの：teddashh/bat-agent-connector（MIT）の考え方（入力待ちの見張り・取り込み前の確認・操作の記録）。BAT 本体には依存しない
- **設定**：Claude Code・Codex の現在版を確認し、［更新を確認して適用］または［モデル一覧を再取得］を押せる。新しいモデルは会話・役割・ターミナルで選べる。使っているモデルや役割は自動で変わらない。役割ごとの担当（AI・モデル・思考）も見て、変えて、保存できる（`_hub/roles.yaml`）
- 台帳の書き方：作業ファイルに `parent: 分岐元の作業ID`、PROJECT.md に `parent: 親プロジェクト名` と `description: 説明` を書ける

Agy（Gemini 3.1 Pro (High)）を使うには、まず Agy CLI を導入し、Googleアカウントでログインしてください。次に Hub の設定でモデル一覧を再取得すると、会話のモデル欄やターミナル起動で Agy を選べるようになります。

Agyのログインは既存CLIで行います。CLI の更新は、設定のボタンを押したときだけ行います。

Grokを使う人は、MacのTerminalで `curl -fsSL https://x.ai/cli/install.sh | bash` によりGrok Buildを導入し、`grok login` でxAIアカウントにログインしてください。Hubは導入コマンドを表示・コピーするだけで実行しません。設定の「AI の更新」でモデル一覧を再取得すると、会話・ターミナル・交代でGrokを選べます。役割分担は導入済み、一覧あり、いずれかのアカウントが状態確認でログイン済みの場合に選べます。ChatGPTは役割の対象外です。モデルはCLIのID、思考は中・高・極高・MAXを使います。

Grokの追加アカウントは `GROK_HOME=~/.hub-accounts/grok/<id>` で分離し、既定から設定・認証・会話をコピーしません。どのアカウントでも `XAI_API_KEY`・`GROK_CODE_XAI_API_KEY` を除外します。追加先では認証ファイル・認証コマンド・OIDC・deployment key・proxyの環境上書きも除外します。API認証と分かる状態は役割で選べません。全経路で自動更新を停止し、更新ボタンで `grok update` を実行します。最新版の確認は公開の `https://x.ai/cli/stable`、導入先の探索はPATHと `~/.grok/bin/grok` です。

Grokの会話はstreaming-jsonを読み、同じアカウント・モデルの場合だけセッションを再開します。思考の指定を拒否された場合は指定を外して1回だけ再実行します。ターミナルからの引き継ぎは画面に残った文字を使います。Grok実物の導入・実行・ログインは未検証です。

## AIアカウント

Gemini（Agy CLI）は既定の行で［状態を確認］できます。契約・無料枠の認証経路で `agy models` を調べ、承認モデルが返る場合だけログイン済みと表示します。API設定は対象外、判定できない応答や時間切れは未確認です。Macのキーチェーンにログイン情報を1件だけ保存するため追加アカウントは作れません。［ログイン］［ログアウト］はTerminalでAgyを開くので、本人が `/login` または `/logout` と入力して操作します。

ChatGPTの行の［ChatGPT を開く］から、アプリでは横のChatGPT、ブラウザではchatgpt.comを別タブで開きます。ログインはそこで行います。Hubは認証情報を扱わず、ログイン状態も確認しません。

役割分担では、状態確認でログイン済みになったClaude Code・Codex・Gemini・Grokを選べます（追加アカウントを含む、ChatGPTは除く）。AIタブを開くと未確認の場合に1回調べ、［もう一度確認］で更新できます。未導入・未ログイン・API認証・未確認は選べませんが、保存済み・編集中の担当は保持します。Geminiはモデル Gemini 3.1 Pro (High)、思考「高」に固定です。役割にGeminiを選ぶとAIへのモデル・委任の指示も追従します。役割の保存時には認証操作を行いません。

Claude Code・Codex・Grokは、設定の「AIアカウント」で名前を付けて［追加］できます。今のログインは「既定」として環境変数・設定・認証をそのまま使います。追加後の［ログイン］はMacのTerminalを開くので、本人が契約アカウントへログインし、戻って［状態を確認］を押してください。Hubにパスワード・トークンは入力しません。［ログアウト］は確認後にCLIのログアウトを実行し、既定はHub以外の同じCLIにも影響するため再確認します。

複数あると、作業の会話のAI選択横・ターミナル上部にアカウント選択が出ます。作業×AIごとに保存し、別作業で別アカウントを並行して起動できます。選択保存中は会話の送信と画面内/外のターミナル開始を待ち、保存完了後の確定アカウントを要求に付けます。保存失敗時は前の選択に戻り、下書きは残します。アカウントを変えると古いセッションは再開せず、人とAIの会話の文字を引き継ぎます。実行中の会話と順番待ちは受付時のアカウントで続けます。画面内の同じ作業・AIのターミナルが動いている間は切替できません。使用中・順番待ち・認証操作中は、そのアカウントのログアウトと削除を拒否します。状態・利用枠の確認中もログアウトと削除を保護します。

名前と場所だけを台帳の `_hub/accounts.json` に保存します。追加先はDocumentsの外の `~/.hub-accounts/<claude|codex|grok>/<id>`（権限0700）で、Claudeは `CLAUDE_CONFIG_DIR`、Codexは `CODEX_HOME` を全起動経路へ渡します。追加先では親やTerminalからのOAuth/sessionトークン、認証用FD/ファイル、ホスト認証や`CLAUDE_SECURESTORAGE_CONFIG_DIR`などの認証上書き入力を除外します。既定はこれらの環境を維持します。Claude Code・Codexでは一般的な設定とCLAUDE.md/AGENTS.mdを引き継ぎ、認証・会話・MCP/外部接続・hooks/API/provider設定はコピーしません。Grokは設定ファイルもコピーしません。追加Codexは `cli_auth_credentials_store="file"` とOpenAI providerを起動引数でも指定し、既定の保存方法は保持します。追加先の外部接続や必要な設定は本人が整えてください。

［削除（ゴミ箱へ）］は追加先の場所ごとゴミ箱へ移します。ClaudeのMacキーチェーン内の項目は、削除だけではログアウトしません。認証も解除したい場合は先に［ログアウト］を押してください。削除したアカウントを選んでいる作業は、次回起動前に選び直します。Agyは既定のみで、Gemini 3.1 Pro (High)の手動選択条件を維持します。

実アカウントのログイン/ログアウト・契約CLIでの同時動作は未検証です。検証では模擬CLI・HUB_DRY_RUNで環境、競合、キュー、会話再開、利用枠、上限保持の分離を確認しています。実ログイン後に別作業へ別アカウントを選び、それぞれの起動と利用枠を確認してください。

## Storage Guard（任意のディスク確認）

`HUB_STORAGE_GUARD` に実行できるディスク確認プログラムを指定すると、起動（`app/run.sh`・`start.command`・Macアプリ）、セットアップ、App作成、更新の前に確認します。起動用の確認は終了コード0で成功とし、更新ではさらに標準出力の `STATUS=OK` が必要です。失敗したら停止し、別の保存先へ切り替えません。未設定なら従来の起動と保存を続けます。確認プログラムは利用者が用意します。

## Project Hub の自動更新

既定でオフです。設定の「Project Hub の自動更新」で切り替えます。設定をまだ保存していない場合だけ、`HUB_AUTO_UPDATE=1` を初期値に使います。保存済みの設定が優先です。

更新元は `kieiken/project-hub` の `main` です。上流の確認は24時間に1回まで。確認時刻を通信前に保存し、失敗・手動要求・再起動をまたいで制限します。［今すぐ更新を確認］も期限前は保存した結果を表示します。設定と記録は `HUB_ROOT/_hub/updates/` に残ります。

macOS、コミット済みGitソースの絶対パス（`HUB_UPDATE_SOURCE`）、更新先の `Project Hub.app` の絶対パス（`HUB_UPDATE_APP`）、`HUB_STORAGE_GUARD` が必要です。設定が揃わない場合は「未対応」と表示します。通常のネイティブAppはソースとAppの場所を起動環境へ渡します。ZIPのソースなどGit履歴が無い環境では使えません。ディスク確認の失敗では通信・保存・更新を止めます。

別のcheckoutで新版を統合し、依存の導入、全テスト、Appの作成と署名検証を済ませます。AI・順番待ち（再起動前に保存した指示を含む）・整理・GitHub操作が残る間と、ソースに未コミットの変更がある間は適用を待ちます。適用直前にソースと署名を再確認し、前のAppとソースを残してから入れ替えます。失敗時は旧Appを保持し、入れ替え途中の中断は保存した記録から復旧します。設定画面自身は自動で読み直しません。ネイティブAppは適用後、AIと順番待ちが無いことを確認して新版を開き直します。

繁體中文版の辞書とlocale境界を導入済みです（`HUB_LANG=zh-TW`、未設定は日本語）。辞書だけでは自動翻訳・翻訳PRを起動しません。有効にする時は、契約ログイン済みのローカルCodex（`gpt-6.1-sol`）とGitHub CLI（`gh`）、`HUB_AUTO_TRANSLATE=1`、`HUB_TRANSLATION_FORK=<アカウント>/project-hub` を設定して使います。API従量課金のキーは翻訳プロセスへ渡しません。翻訳は隔離コピー内で実施し、個人の台帳を読みません。

PRは確認済みの公開forkの `automation/zh-tw`（`HUB_TRANSLATION_BRANCH` で指定可）へ送り、作者の `main` を対象に作成・更新します。作者の `main` を直接変更しません。全テスト・ビルド・署名・公開対象の検証を通したコミットだけを送り、PRの対象・URL・コミットを読み戻して確認します。翻訳・PR送信の試行時刻も保存し、失敗や中断後の再試行は24時間に1回まで。PR送信の失敗はAppの適用状態と別に表示します。利用者が自動送信を有効にした場合の処理であり、この設定を有効にしなければ送信しません。AI CLI自体の更新は従来の「AI の更新」で行います。

## 手動で最新にする

Gitで取得したフォルダの一番上で実行する（ZIPで取得した場合は、新しい版の配布物を取得する）：

```
git pull --rebase
```

取り込むと、画面の上に［新しい版 vX.Y.Z にする］が出る。押すと本体が起動し直して新しい版になる（動いている AI がある時は、止めてから押す）。
アプリ（window.swift）が変わった時だけ `bash hub/app/build-app.sh` も実行する。

## 仕組み（作る人向け）

- **更新するたびに版を上げる**：`package.json` の version と `CHANGELOG.md` の一番上を同じ番号にする（違うとテストが落ちる）。機能を足したら2つ目、直しただけなら3つ目、大きな作り直しは1つ目を上げる

- `server.js`：Node.js で動く（画面内の作業画面には node-pty を使う）。`127.0.0.1:4545` だけで待ち受け、他のサイトからの操作は受け付けない
- `lib/frontmatter.js`：台帳の先頭部分を読む ／ `lib/store.js`：台帳と作業ファイルの読み書き ／ `lib/launch.js`：起動コマンドの組み立て ／ `lib/sessions.js`：画面の中の作業画面（node-pty） ／ `lib/roles.js`：役割分担の読み書き ／ `lib/git.js`：作業用コピーの作成・取り込み・片付け
- `public/`：画面（`vendor/` に xterm.js を同梱） ／ `seed/`：最初の台帳 ／ `test/`：`node --test --test-force-exit hub/test/*.test.js`
