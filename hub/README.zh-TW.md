# Project Hub

[日本語](README.md) | 繁體中文

目前版本以 `package.json` 的 `version` 為準，畫面左上角也會顯示。完整變更紀錄見 [CHANGELOG.zh-TW.md](CHANGELOG.zh-TW.md)。

這是集中管理專案與任務、在同一個畫面中執行 Claude Code / Codex 的軟體。主要供一個人在自己的 Mac 上使用；也可自行啟用受密語保護的 Tailscale 遠端操作。請先閱讀「使用前須知」。

## 第一次使用（只需一次）

必要條件：Node.js 22 以上、Git，以及已安裝並登入的 AI CLI（Claude Code / Codex）。也需要 Apple 開發工具；若尚未安裝，`setup.sh` 會顯示安裝視窗並停止，安裝完成後重新執行即可。

進入下載或複製的專案最上層（包含 `hub/` 的位置），執行：

```sh
cd "<取得的專案資料夾>"
HUB_LANG=zh-TW HUB_APP_DIR=/Applications HUB_ROOT="/Volumes/External/AI-Workspace" bash hub/setup.sh
```

`/Volumes/External/AI-Workspace` 是範例，請替換成自己的資料磁碟位置。執行前先依本機規則檢查掛載與可用空間；資料碟無法使用時，停止依賴該磁碟的操作。

- 可以重複執行。
- 在 `HUB_ROOT` 下建立 `_hub/`（角色分工 `roles.yaml`）、`Product/`（專案台帳）與 `Work/`（工作副本）。預設為 `~/Documents/AI-Workspace/`；既有 `roles.yaml` 與台帳不會被覆寫。
- `HUB_LANG=zh-TW` 使用語系包 `hub/locales/zh-TW/` 中的繁中範本與虛構範例台帳；未設定或 `ja` 使用內建日文版。台帳會複製到 `Product/`，不代表真實專案或工作紀錄。範例路徑需自行調整。
- 透過 npm 安裝內嵌終端機元件 node-pty。安裝失敗時仍可使用管理功能，AI 工作改在另一個視窗開啟。
- 建立 Project Hub.app 與桌面入口。透過 `HUB_APP_DIR=/Applications` 將程式本體放在系統應用程式資料夾，持續增長的資料、快取與編譯暫存則依本機規則放在資料碟。

## 使用前須知

- **單一使用者的 Mac**：服務只監聽 `127.0.0.1:4545`，會檢查 Host 與 Origin，本機操作沒有登入驗證。不要作為公開 Web 服務或多人共用伺服器。遠端操作須另外啟用密語驗證，見「從外部使用（iPhone）」。
- **AI 權限確認**：預設 Claude Code 使用 `--dangerously-skip-permissions`，Codex 使用 `--dangerously-bypass-approvals-and-sandbox` 啟動（`lib/launch.js`）。前者略過權限確認，後者同時略過權限確認與沙箱。AI 可使用你的帳號權限修改檔案與執行指令；可在 `_hub/roles.yaml` 的 `permissions` 調整啟動方式。
- **會被複製的設定**：建立工作副本時，會複製主專案最上層尚未納入 Git 的 `.env`、`.env.*`、`.dev.vars`、`.dev.vars.*`、`.npmrc`，以及 `.claude/settings.local.json`，讓 AI 能執行專案測試。
- **自動 Git 儲存**：開始工作前、首次儲存與合併工作副本時，會先 `git add -A` 再提交。提交不顯示終端機確認，使用 `--no-verify`，因此不執行 pre-commit 等 hooks。未設定 Git 身分時使用 `Project Hub <hub@localhost>`。
  - 新增的 `.env` 類檔案、`.npmrc`、`.dev.vars` 類檔案與 `.claude/settings.local.json` 會排除於提交，即使先手動 `git add` 也會取消這些新檔案的暫存，但保留本機檔案。`.env.example`、`.env.sample` 作為範例會納入提交。
  - 已被 Git 追蹤的檔案、繞過 Hub 手動提交的檔案，以及其他名稱的機密檔案不受此保護。無法保證秘密資訊不會進入 Git；需要時請在各專案 `.gitignore` 排除。
- **本機紀錄**：對話 `.ai/chat/`、交接資料 `.ai/handoff/`、操作紀錄 `_hub/log.jsonl`、傳入檔案 `AI-Workspace/Inbox/hub/` 都不加密。既有 Git 專案的對話與交接資料可能被自動提交；不希望納入時請寫入各專案 `.gitignore`。新專案範本已附排除規則。分享或公開前請確認內容。
- **費用**：實際使用 AI 的費用由各 AI CLI 的方案、費率與登入設定決定，Hub 不保證免費。
- **對外操作**：公開、發文、寄送等將工作內容送到第三方服務的操作，仍需由人逐次批准；Hub 的工作流程不代表已取得這些授權。

## 每次使用

按兩下桌面的「Project Hub.app」，即可在專用視窗開啟，不需要終端機。第一次可能會詢問存取「文件」資料夾的權限，請在需要使用時允許。

- 應用程式（`app/window.swift`）會啟動 Node.js 服務（`node server.js`），並使用 Mac 內建 WebKit 顯示畫面。
- 關閉視窗後，服務與執行中的 AI 會繼續在背景執行；再次開啟即可接續。
- 啟動失敗時，視窗會顯示原因。預設紀錄為 `~/Library/Logs/ProjectHub.log`，也可從選單的「開啟紀錄」查看；若已依本機規則另設紀錄位置，以實際設定為準。
- `app/build-app.sh` 會重建應用程式，`setup.sh` 也會呼叫它。更新原生視窗程式後請執行重建。
- 重新命名等輸入對話框支援 ⌘V 貼上。包含原生視窗修正的更新，除了重啟 Hub 服務，也需要重建 Mac 應用程式。
- 如需從終端機啟動，執行 `bash start.command`。

## 功能

- **檔案與資料夾連結**：點選後選擇開啟方式。檔案可「開啟原始檔案」或「在 Finder 顯示」；資料夾可「在 Finder 開啟」或「查看內容」。使用原始位置，不下載副本。Mac 應用程式與瀏覽器皆可使用。
- **整理與執行驗證**：顯示候選項目取得狀態。選取後可「移到垃圾桶」，並從整理紀錄還原；中止時顯示原因。結構檢查會從專案位置解析資料的相對路徑。
- **左側樹狀清單**：專案下列出任務。子任務與子專案以「↳」縮排；分支任務與來源保持同一層，標示「⑂ 分支」。數字表示分支數。
- **專案概要**：點選專案查看說明、任務、階段、負責人、問題與相關專案。「查看檔案」可開啟內容所在位置，有多處位置時先選擇。
- **對話畫面**：在任務畫面的「對話」中，以單一對話完成工作，類似 Goose。每次送出時可選擇 AI、模型與思考程度，回覆會標示回答者。切換 AI 時，會附上新 AI 尚未讀過的人與 AI 文字對話；同一個 AI 則接續其原有會話。對話存於 `.ai/chat/<任務ID>.jsonl`；內部逐次執行 `claude -p --output-format stream-json` 與 `codex exec --json`（`lib/chat.js`）。需要查看詳細執行過程時切換到「終端機」。
- **專案狀態圓點**：灰色＝尚未開始；紅色＝AI 執行中；淺綠色＝處理結束；紫色＝已完成（只有按「將專案標為完成」才成立，可取消）。任務使用相同顏色，黃色表示需要你回覆。
- **路徑與 URL**：點選對話或問題中的資料夾路徑，可在畫面內查看內容；檔案可用對應程式開啟，也可選擇 Finder。URL 用瀏覽器開啟，⧉ 可複製。
- **詳細執行內容**：預設不在對話顯示指令等細節，可在設定的「對話畫面」開啟。
- **檔案權限**：無法讀取文件等資料夾時，可在設定或應用程式選單按「再次顯示權限確認」，並在 macOS 視窗允許；若未顯示，可在系統設定加入「完整磁碟存取權」。
- **AI 問題**：需要你判斷時，對話會出現選項按鈕；選擇後送出回答。任務會呈現等待回覆的黃色狀態。
- **模型清單**：只顯示 CLI 回報可用的模型，可在設定的「顯示於選單的模型」隱藏。使用「整理為最新模型」可更新角色設定中的舊模型名稱。
- **AI 委派給 AI**：必須透過 Hub 的 `/api/delegate`，在同一任務與對話切換 AI。若已有 AI 執行，先排隊，結束後再開始；不增加子任務。畫面可查看等待順序、執行中的 AI／模型與結果。需指定 `model` 或主要負責角色 `role`；支援正式模型名稱，例如 `claude-fable-5-1`。未指定或無法使用時會回報原因並停止，不擅自改用預設模型。終端機執行中無法委派，需改從同一任務的對話畫面繼續。啟動失敗時保留狀態與問題，已完成任務須由人重新開始才能委派。繞過 Hub 在背景啟動的 AI 也會被監看並顯示「背景工作中」。
- **子專案**：透過「拆成子專案」同時開始多個子專案。子專案完成後，結果回到上層任務與對話並標示「新」；子專案尚未結束就啟動上層工作時，會先提醒。
- **ChatGPT**：選擇 ChatGPT 後，Hub 會產生包含任務、台帳與近期對話的文字，複製後貼到 ChatGPT；再將回覆貼回 Hub，可選擇讓 Codex 接續。Mac 應用程式可在旁邊開啟 ChatGPT。進階設定的「註冊到 ChatGPT 應用程式（Codex）」是 Codex 的 MCP 設定入口，一般 ChatGPT 對話不會因此自動取得本機工具。「允許實際工作」預設關閉。
- **從外部使用（iPhone）**：在設定啟用並設定通關密語，Mac 與 iPhone 安裝 Tailscale，Mac 執行 `tailscale serve --bg 4545`。在 iPhone 開啟 `https://<Mac名稱>.<tailnet>.ts.net` 並輸入密語。登入後可使用與 Mac 相同的功能；處理仍在連線的 Mac 上執行。
- **未讀與 GitHub**：沒有查看時 AI 工作結束，左側清單會出現「未讀」；開啟任務對話後解除。已合併整理的任務通知會移除，已完成但未讀的任務會留到讀取為止。主專案位於 GitHub 時可按「GitHub」開啟，工作副本會開啟對應分支。
- **快速開始**：在專案畫面寫下想做的事，按「開始」，即可建立任務並送到對話中的 AI。可選 AI、模型與思考程度，專案會記住上次選擇；尚未儲存選擇時使用設定的初始 AI，預設為 Codex／GPT-6.1-Sol／高。文字與圖片草稿會在重繪、切換與重啟後保留，成功送出後清空。可拖曳、⌘V 或按附件鈕加入最多 10 張圖片（png/jpg/jpeg/webp/gif/heic），也可只送圖片，送出前按 × 取消。原圖與必要的 PNG 存於任務資料夾 `attachments/<任務ID>/`；Claude 使用 Read 指示、Codex 使用 `exec -i`，Agy 接收圖片路徑。GIF 會取第一格轉成 PNG。Discord 未支援送出，因此保存需求與圖片位置，並標示未送出與手動交接方式。要詳細設定時可按「＋ 詳細設定並新增任務」。
- **對話圖片預覽**：拖入或用 ⌘V 貼上圖片後，會在需求上方顯示縮圖，可按 × 取消。僅圖片也能送出；切換、重繪或送出失敗時仍保留附件。重啟後的草稿復原只支援快速開始欄。送出時將圖片位置附於需求；其他檔案仍以路徑加入本文。
- **執行中的指示**：AI 執行時可選「① 取消並重做」「② 補充說明（一起處理）」「③ 完成後接續」。第三種依順序自動開始，保存後重啟仍保留；停止中可按「▶ 開始」送出。「停止」也會取消等待中的指示。
- **新專案**：左側清單底部按「＋ 新專案」，輸入名稱、說明與階段；主資料夾、上層與相關專案在「詳細設定」。Hub 會建立台帳、AI 指示與工作資料夾。
- **任務畫面**：點選任務後以完整視窗顯示 AI 工作畫面。「用 Claude Code 開始」或「用 Codex 開始」啟動，亦可按「＋ 並排」讓兩者同時工作。
  - 「切換給另一個 AI →」用於額度用完或更換模型。將前一 AI 的人與 AI 文字對話整理到 `.ai/handoff/`，不含工具結果、附件或隱藏推理，再由新 AI 讀取接續。未執行的新 AI 按角色設定啟動；正在執行時會拒絕交接。對話從 Claude Code／Codex 紀錄（`~/.claude`、`~/.codex`）取得，讀取失敗則以終端機畫面文字代替。超過 6 萬字時省略較舊內容並註記，不刪除原始對話。此設計參考 arumwu/goose-acp-handoff，沒有 Goose 依賴。
  - 修改 AI 標題的模型與思考程度，會向執行中的 AI 輸入 `/model`、`/effort` 切換，也會保存至任務檔。
  - 有 Git 的專案按「開始」時自動建立任務工作副本 `Work/<專案>/<任務ID>/`，AI 在副本工作。沒有 Git 時先建立 Git 儲存，再於主專案工作；每次開始前都會自動儲存。
  - 「排除合併」隱藏合併按鈕與差異預告，不影響副本、檔案與接續位置。之後可恢復合併，排除期間仍能在原處工作，也會計入剩餘副本數。
  - 「合併到主專案」將副本變更合併，再把副本移至垃圾桶。衝突時不合併，並在「輪到你了」提示；AI 執行中無法合併。
  - 下方可修改狀態與備註；AI 未執行時也可指定下一次啟動的模型與思考程度。
- **負責人與進度**：以顏色與形狀辨識負責人：圓形是 Claude Code／Codex，方形是 Discord 代理，黃色是你。根據任務檔的「## 步驟」（也相容日文「## 手順」）顯示進度；全部勾選後進入完成確認，仍需人的確認才正式完成。
- **階段**：概要頂部顯示階段路線。當前階段任務全部完成後，顯示 COMPLETE 與「前往下一階段」。任務清單預設展開目前階段，其他階段收合。
- **通知意義**：左側顯示「未讀」「等待回覆」「確認完成」。未讀是尚未開啟的 AI 結果；等待回覆包含問題、額度用完停止與 AI 等待輸入超過 1 分鐘；確認完成是等待「標為完成」或「繼續進行」的決定。有問題的任務計入等待回覆。
- **輪到你了**：上方按鈕分別列出等待回覆與確認完成數量，可從對應分頁回答或決定是否完成。
- **執行中／等待輸入**：AI 終端機畫面 20 秒未更新時，會顯示「等待輸入」；Claude Code／Codex 執行時通常會持續更新。
- **合併前預覽**：「合併到主專案」旁顯示變更檔案數、行數與可能衝突提醒。建立副本時也會複製未納入 Git 的本機設定，如 `.env`。
- **傳入檔案與截圖**：拖入 AI 終端機或用 ⌘V 貼上，會保存到 `AI-Workspace/Inbox/hub/<日期>/`，並將路徑放進 AI 輸入欄；接著可輸入指示並按 Enter。任務備註也會留下路徑，供另一個或下一個 AI 讀取。AI 未執行時只保存檔案與紀錄。
- **操作紀錄**：開始、停止、交接、合併等操作存於 `_hub/log.jsonl`，可在設定的「最近操作」查看。監看等待輸入、合併確認與紀錄的設計參考 teddashh/bat-agent-connector（MIT），不依賴 BAT 本體。
- **設定**：查看 Claude Code／Codex 目前版本，按「檢查並套用更新」或「重新取得模型清單」。新模型可用於對話、角色與終端機；不會自動更改目前模型或角色。角色的 AI、模型與思考程度可修改並存到 `_hub/roles.yaml`。可設定新專案、子任務與分支的初始 AI；預設 Codex／GPT-6.1-Sol／高。也可調整模型顯示、排序與手機上的短名稱。
- **台帳格式**：任務可寫 `parent: <來源任務ID>`，`PROJECT.md` 可寫 `parent: <上層專案名稱>` 與 `description: <說明>`。欄位名稱與內部角色、狀態值保留原有格式，繁中範本已附註用途。

使用 Agy（Gemini 3.1 Pro (High)）前，先安裝 Agy CLI 並用 Google 帳號登入，再於設定重新取得模型清單，即可從對話模型選單或終端機啟動 Agy。

Hub 不修改 CLI 的登入驗證。CLI 只在按下更新按鈕時更新。

## 使用量顯示

Hub 從已安裝的 Codex（ChatGPT 帳號登入）與 Claude（訂閱帳號登入）CLI 取得訂閱額度使用比例，與精確 token 數或對話上下文使用量不同。上方使用量按鈕可查看各額度的重設時間與剩餘時間。

不執行推理、付費 API 呼叫或購買，也不修改登入與收費設定。秘密資訊與 CLI 原始輸出不會送到 Hub API。未安裝、未登入或內部規格改變時顯示尚未取得，可按「查看目前使用量」重試。Claude 的 `control get_usage` 是內部介面，未來版本可能無法取得。檢查不會重繪或停止現有任務。

## 模型與思考程度

初始角色設定：統籌與審查使用 Fable 5.1；研究、設計與寫作使用 Opus 5.5；圖片生成與程式開發使用 GPT-6.1-Sol。備援欄位一般是取得人類批准後才切換的候選；對話中的統籌與審查遇到正式確認的 Fable 使用上限時，現行版本另有一次交接至 Astra 的處理。其他認證或連線錯誤不會因此更換 AI。`setup.sh` 不覆寫既有 `_hub/roles.yaml`。

`lib/launch.js` 的 `MODEL_FLAG` / `EFFORT_FLAG` 將畫面名稱轉成 CLI 參數；執行中切換的指令在 `SWITCH_CMD`。CLI 支援的名稱改變時，只需更新對應設定。

## 後續規劃

## Project Hub 自動更新

公開版本預設關閉。可在設定的「Project Hub 自動更新」開啟「自動更新 Project Hub」。尚未保存開關設定時，`HUB_AUTO_UPDATE=1` 用作預設值；已保存的開關優先，所以之後仍可從設定關閉。

只檢查原作者的 [kieiken/project-hub](https://github.com/kieiken/project-hub) `main`，不把個人 fork 當成新版來源。兩次上游新版檢查至少間隔24小時；檢查時間會保存，重啟只在期限已到時檢查，不額外增加次數。「立即檢查更新」在當天已查過時顯示保存的結果與下次時間，不繞過每日限制。畫面讀取保存的狀態不是另一輪新版檢查。

設定會顯示「目前版本」「最新版本」「上次檢查」「下次檢查」與更新狀態。AI 執行中、尚有排隊指示、原始碼未提交或其他工作尚未結束時，先保留待更新狀態，等可以安全處理再繼續。

更新先在隔離的原始碼副本整合上游，再用目前已登入的 Codex CLI 補齊繁中介面、指示與文件。完成相依套件安裝、完整測試、公開內容檢查、App 編譯與簽章驗證後，才替換 App，保留舊 App 與原始碼副本供復原。專案台帳、對話、AI CLI 登入與角色設定不因更新被重建。

通過驗證的翻譯會推送到已設定的個人 fork 分支，再提交到原作者 `kieiken/project-hub` 的 `main`，以 Pull Request 請原作者合併；不直接改寫原作者的 `main`。確認 PR 已建立後，設定顯示「查看翻譯 PR」。提交 PR 不代表原作者已接受或合併。

完整的繁中與 PR 同步流程需在 App 的啟動環境設定 `HUB_AUTO_TRANSLATE=1` 與 `HUB_TRANSLATION_FORK=<你的帳號>/project-hub`，並先登入 Codex CLI 與 GitHub CLI（`gh`）。fork 必須是原作者專案的公開 fork，且目前帳號可以推送。預設使用 `automation/zh-tw` 分支，可用 `HUB_TRANSLATION_BRANCH` 指定其他分支。設定畫面只在流程有設定時顯示翻譯與 PR 提示；只開啟自動更新開關，不代表這些登入與發佈設定已完成。

更新編譯仍需要 Git、Node.js 22以上與 Apple 開發工具。一般公開安裝不會自動代替使用者設定登入或發佈目標。從 Finder／Dock 開啟時須讓 GUI 程序取得同一組環境設定；只在一次終端機指令前設定變數，不會自動保留到之後的桌面啟動。

自動替換 App 只支援已完成設定的 macOS 環境。啟動環境還需要 `HUB_UPDATE_SOURCE`（含本次繁中與更新修改、已提交的 Git 原始碼位置）、`HUB_UPDATE_APP`（名為 `Project Hub.app` 的更新目標絕對路徑，其上層資料夾須存在），以及可執行的 `HUB_STORAGE_GUARD` 磁碟檢查程式。只有下載可攜式 `.app`、沒有 Git 原始碼或這些設定時，會顯示尚未支援，不能只開啟開關就當成已可更新。磁碟檢查未通過時，不查 GitHub、不寫入更新資料，也不改存到其他位置。

本次繁中 PR 尚未合併到原作者版本時，更新必須保留本機繁中與更新功能的修改，再整合新版。不是直接下載日文程式覆蓋。若來源無法相容合併，或翻譯、測試、編譯、簽章失敗，會保留舊版並顯示原因或待處理狀態；不能保證所有未來版本都能自動成功。PR 傳送結果另外顯示，傳送失敗不能當成已送出，也不等同 App 未安裝。請先處理提示的原因，再依畫面狀態繼續，不重複建立相同版本的 PR。

設定、檢查與更新狀態保存在 `HUB_ROOT/_hub/updates/`；隔離的原始碼與處理紀錄也保留在此，方便核對與復原。檢查失敗也保留嘗試時間，避免重啟反覆查詢；若資料磁碟已不可寫，檢查會停止，只能在目前程序記住嘗試時間。這是 Hub 本身的更新；設定中的「AI 更新」仍是另外操作，不會自動更新 Claude Code、Codex 或其他 AI CLI。

## 手動更新

自動更新關閉或暫時無法使用時，可用以下方式。請先確認原始碼狀態與可復原備份，不要直接覆寫執行中的版本。

在 Git 專案最上層執行；使用 ZIP 安裝時，重新取得新版公開檔案：

```sh
git pull --rebase
```

取得後，畫面頂部會顯示「更新為 vX.Y.Z」。按下會重啟服務並套用新版；有執行中的 AI 時，需先停止。`window.swift` 或應用程式建置設定變更時，也要執行：

```sh
HUB_LANG=zh-TW HUB_APP_DIR=/Applications bash hub/app/build-app.sh
```

請沿用原有 `HUB_ROOT`、快取與暫存設定；需要更換應用程式前，依本機規則保留可復原備份。

## Mac App 的建置範圍

目前的 `build-app.sh` 建立此電腦上的 App，並指向原始 Hub 資料夾；該資料夾、Node.js 22 以上與已登入的 AI CLI 仍須保留。

GitHub Actions 會執行日文與繁中測試、乾式公開檢查，建立包含 Hub 程式的繁中 App 並提供 ZIP 與 SHA256。執行仍需另外安裝 Node.js 22 以上及已登入的 AI CLI；不是包含 Node.js 的完整獨立執行檔。以 `HUB_BUNDLE_RUNTIME=1` 建置時，Hub 程式、繁中辭典、範本與範例放在 App 內，位置會隨 App 移動。一般建置仍使用原始碼位置。C 已加入的 `HUB_LANG=zh-TW` 會寫入 App 預設語言；啟動時設定 `HUB_LANG` 可覆蓋該預設。工作資料與 App 分開，須保留原 App、設定與資料的可復原備份。

## 運作方式（開發者）

- **每次更新都提高版本**：`package.json` 的 `version` 與 `CHANGELOG.md` 最上方版本一致，否則測試失敗；繁中變更紀錄也請同步。新增功能提高第二碼、修正提高第三碼、大幅改寫提高第一碼。
- `server.js`：Node.js 服務，內嵌終端機使用 node-pty；只監聽 `127.0.0.1:4545`，拒絕其他網站的操作。已啟用的遠端操作另經密語驗證。
- `lib/frontmatter.js`：讀取台帳檔頭；`lib/store.js`：讀寫台帳與任務；`lib/launch.js`：組合啟動指令；`lib/sessions.js`：內嵌終端機；`lib/roles.js`：角色分工；`lib/git.js`：建立、合併與整理工作副本。
- `public/`：介面，`vendor/` 隨附 xterm.js；`seed/`：日文初始台帳；`test/`：`node --test --test-force-exit hub/test/*.test.js`。
- `locales/<語系>/`：日文以外的獨立語系包（目前為 `zh-TW`）。日文內建於程式本體；`HUB_LANG` 指定的語系包不存在時改用日文。新增語言只要新增一個資料夾，不需修改程式本體：必備 `pack.json`（`locale` 與資料夾名稱相同、`name`、`dateLocale`），其餘依需要放入 `messages.json`（伺服器 `lt`）、`ui-messages.json`（僅畫面使用的文字）、`terms.json`（標題、狀態與角色的顯示名稱）、`native.json`（Mac App 與 Info.plist）、`ui.css`、`seed/`、`templates/`（`_hub/`、`project/`）。辭典的鍵是日文原文，插入值寫成 `${0}` 等形式。
- `locales/zh-TW/templates/`：繁中專案與角色範本。角色識別碼、狀態、思考值與既有資料夾鍵使用原有格式；畫面依語言顯示中文。

## 複製、刪除、整理與檢查

對話文字框右上角的「複製」只複製內容。右鍵「刪除…」會先列出要移至垃圾桶的項目，以及為共用保留的項目；AI 執行、排隊、有子項目或工作副本時無法移動。可從「整理與檢查」的紀錄還原，同名檔案不會被覆寫。
