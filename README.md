## 前提

- macOS
- Node.js 22 以上、Git
- 使う AI の CLI（Claude Code / Codex）を入れて、ログインしておく
- 作業画面の部品（node-pty）とアプリ（Project Hub.app）を作るには、Apple の開発ツールが必要

## はじめる

取得したフォルダの一番上（この README がある所）で、次を実行します。

```
bash hub/setup.sh
```

- `~/Documents/AI-Workspace/` に `_hub/`・`Product/`・`Work/` を作ります。場所は `HUB_ROOT` で変えられます
- 何度実行しても大丈夫です。すでにある `roles.yaml` と台帳（`PROJECT.md` があるフォルダ）は触りません
- npm で node-pty を入れ、デスクトップに Project Hub.app を作ります

使い方・更新のしかたは [hub/README.md](hub/README.md) を見てください。

## Codex・Claude の元の会話をリンクする

設定の［Codex・Claude の会話をリンク］から［グループ・会話を選ぶ］を押し、必要なものだけを選びます。最初はすべて未選択です。［選んだ内容を確認］で件数・足りない記録・読み取りの注意を確かめてから、［確認してリンクする］を押してください。

Hub は元の記録へのリンクだけを保存し、会話のコピーや新しい作業は作りません。会話・コード・作業フォルダは元の場所に残ります。表示する時は元の人と AI の文字を読み取り、ログイン・OAuth 認証・権限設定・添付・道具の結果・隠れた推論は移しません。リンクを保存しても AI は動きません。［リンクだけを外す］で Hub の入口だけを外せます。元の記録が見つからない時もリンクを残し、理由を表示します。

左の［外部の会話］でリンクを開き、［同じ会話へ送る］を押すと、Claude は元の会話 ID で再開し、Codex は同じ thread ID を読み取って再開します。元の道具が既存のログインと権限を使い、元の作業フォルダで動いて新しい番を保存します。許可が必要な操作は人が確認し、停止は今回起動したプロセスだけを中断します。元の記録が変わった、見つからない、または実行中の時は止め、新しい会話や分岐へ切り替えません。

元のアプリと Hub は同じ会話記録を使います。元の会話を開き直すと、元のアプリでも読めます。両方の画面が同時に更新される保証はありません。道具が同じ会話 ID を返し、元の履歴が更新されたことを確認してから完了にします。失敗や再起動の後に送信結果が分からない時は、元の会話を確認してから再送してください。

リンクと再開は本体でのみ操作できます。読み取り上限を超えた、または途中で元の記録が変わった時は理由を示して止め、会話を黙って切り詰めません。Hub を使わずに動く [AI Session Exporter](https://github.com/arumwu/ai-session-exporter) でも、同じリンクと元の会話の再開、選んだ会話の JSON／Markdown 出力を使えます。

## 注意

- **AI の許可と作業範囲**：Hub の作業は Claude Code の `--permission-mode acceptEdits` と Codex の `--sandbox workspace-write` で起動します。書き込み先は実際の作業フォルダと、その Hub プロジェクトの台帳フォルダです。作業用コピーから元のコードや参照フォルダへ書き込み範囲を広げません。古い `roles.yaml` の広い許可指定も起動時にこの範囲へ絞り、設定ファイル自体は書き換えません。リンクした元の会話は、元の道具の既存の権限で再開します。
- **料金**：AI の料金・プラン・課金のしかたは、各 CLI 側の設定に従います。Project Hub は料金がかからないことを保証しません
- 自動の Git 保存、作業用コピーに写す設定ファイル、手元に残る記録などの注意は [hub/README.md](hub/README.md) にあります

## テスト

```
HUB_SKIP_NPM=1 npm --prefix hub test
```

node-pty が入っていない時は、作業画面を実際に動かす確認は省きます。

## 同梱の初期台帳（seed）

`hub/seed/` には、架空の「サンプルアプリ」「サンプルサイト」「サンプル文書」「Project Hub」の台帳が入っています。実際のプロジェクトや作業の記録ではありません。`setup.sh` はこれらを `Product/<名前>/` に写します。

## この公開物について

このフォルダは、Project Hub の部分だけを Git の履歴なしで切り出したものです。Git の作業コピーで `node scripts/export-public.js` を実行すると、コミット済みのファイルから `public-release/ProjectHub` に作り直せます。製品コードの版を固定する時は `--ref <コミット>`、公開用文書だけ別のコミットから使う時は `--public-ref <コミット>` を指定します。

- 実際の作業の記録（`.ai/` の会話・引き継ぎなど）は入っていません。ひな形と架空の台帳に必要な `.ai/` のファイルだけを入れています
- 公開版の [CHANGELOG](hub/CHANGELOG.md) は 4.20.0 から始まります（それより前の記録は過去の資料を含むため外しています）
